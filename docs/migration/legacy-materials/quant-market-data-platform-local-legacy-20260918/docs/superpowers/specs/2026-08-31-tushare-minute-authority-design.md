# TuShare 分钟数据权威来源与历史回补设计

## 目标

让 TuShare `stk_mins` 成为 A 股唯一的现行分钟数据源。先修复
2026-07-08 至最新日期的数据尾部，再恢复受控的夜间历史回补，
从 2016-01-04 开始向供应商实际提供的最早日期推进。

## 当前证据

- 本地 TuShare 接口在 2016-01-04、
  2020-01-02、2021-07-01、2022-07-14 和 2022-07-15 为 `000001.SZ` 返回了 241 根数据。
- 因此，2022-07-15 是上一轮回补的起点，不是供应商数据范围的下界。
- 当前 TuShare 运行别名已覆盖至 2026-08-28。
- Guan 提供的 `minute_1m` 别名仍是现有规范别名。TuShare 替代版本通过验证前，不得覆盖该别名。

## 设计

### 阶段一：修复当前数据尾部

使用现有的 TuShare 241 根数据回补实现，获取 2026-07-08 至最近完整交易日之间缺失的所有交易日。数据只能写入 `assets/derived/a_share/` 下的新不可变版本。完成每个日期的完整股票池校验，并在回执通过后原子更新 `minute_1m_tushare`。本阶段不得修改 `minute_1m`。

### 阶段二：历史夜间回补

恢复一条受控的夜间回补任务，继续使用现有请求配额台账、33 的批量大小、241 根数据校验、运行时限、可恢复旁车文件和硬停止机制。从 2016-01-04 开始，先用少量代表性股票探测更早日期，再生成大规模计划。只有在某个日期既有供应商数据，又能被运行流程可靠获取时，才将其视为有效日期。不能根据单只股票的空响应推断数据下界。

同一时间只能运行一条历史回补任务。任务只能写入暂存数据和回执，不能直接写入生产别名。评估期间保留现有 Guan 数据作为回滚来源。

### 阶段三：切换权威来源

TuShare 数据范围连续并通过结构和语义检查后，重新计算 TuShare 原生特征和 DailyWatch20 输入。只有在策略与数据源评审明确批准新数据体系后，才能切换唯一的 `minute_1m` 别名。保留旧 Guan 版本及其覆盖回执作为冷回滚产物，不再放入现行输入路径。

### 运行计划简化

现行调度只保留：

1. one TuShare daily operational updater;
2. one shared quota coordinator;
3. one resumable historical backfill campaign while history is incomplete.

替代任务变体、日历或模型修复变体，以及沪深观察名单分钟覆盖任务，在保留有用回执后全部停用。版本保留策略只保留现行版本和一个回滚版本。较旧的不可变目录和原始暂存数据完成备份核验后移入冷存储。

## 安全要求与验收标准

- systemd 缺少 `TUSHARE_TOKEN_2` 时，必须在任何部分数据发布前失败，并生成监控程序可见的失败结果。
- 每个已发布日期都必须具备完整旁车文件、预期股票池、241 根分钟网格、唯一键、有效模式和回执哈希。
- 下载失败或数据不完整时，绝不推进别名。
- 首轮实现不得删除数据、切换 `minute_1m`，也不得改变 DailyWatch20 策略模式。
- 验收结果必须报告日期范围、交易日数量、行数、缺失日期、供应商最早可用日期，以及仍处于启用状态的确切文件和单元。
