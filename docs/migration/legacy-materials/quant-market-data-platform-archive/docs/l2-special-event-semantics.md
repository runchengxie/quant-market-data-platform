# L2 特殊事件语义

本文记录 105 GiB pilot 中 `Price <= 0` 行的首日处理决定。这是分类决定，
供应商编码仍需后续证据才能完成唯一解释。

## 观察结果

在 `deal_20260424.parquet`（194,296,495 行）中，有 36,317,914 行（18.692%）满足
`Price == 0`。这些行的 `Side` 只有 `-11` 和 `-1`，对应的买方或卖方标识为零。
这与抽样检查中的普通正价格成交明显不同，后者的 `Side` 为 `0` 或 `1`。

`deal_20260416.parquet` 中也出现了相同模式。因此，这些行更像特殊竞价、未撮合或占位事件，
不像普通成交。现有字段还不足以确定唯一的供应商语义。

## 处理决定

- 保持原始行不变。
- 增加稀疏 sidecar 标签，内容为 `decision=tag` 和
  `reason=special_price_or_event`。
- 只有下游数据集契约明确要求可执行的正价格成交时，才允许排除这些行，并在 manifest 中记录排除情况。
- 不通过排序或重写原始流来修复 `deal_20260416` 中观察到的时间戳重置。保留源顺序，并公开重置诊断。

对于快照，非正价格解释为空盘口档位，并标记为 `empty_snapshot_price`。这些行不会自动删除，
因为零价格可以是表示档位不存在的有效哨兵值。

比较包含和不包含标签行时的模型与回测结果后，可以修订这项政策。无论最终决定如何，原始层都保持不可变。
